# 條號地圖技能 (condition-map)

## 功能說明

此技能將某一**主題**（例如「無權代理」、「羈押」、「行政處分」）的相關法條，整理為固定 7 欄位輸出的「條號地圖」筆記。

**核心目的**：讓使用者上課聽到老師講「§170」「§118」「§169」這類條號時，能秒反應出該條的功能、所在體系位置、與相鄰條號的關係，把條號當「符號語言」即時跟上講課脈絡，而不是事後回頭翻法條。

### 與其他 skill 的差異

| Skill | 定位 | 輸出 |
| --- | --- | --- |
| `subtitle-note-organizer` | 把整份字幕拆成多個主題的完整學習筆記 | 法條原文 + 一試重點 + 體系圖 + 案例分析 |
| `topic-note-organizer` | 把多年考古題依主題彙整 | 題目分類 + 出題趨勢 + 重點整理 |
| **`condition-map`（本技能）** | **單一主題的條號索引地圖** | **條號功能標籤 + 路徑圖 + 對照表 + 影片對照提示** |

`condition-map` 不取代上述兩者，而是作為「上課即時對照工具」。可以單獨使用，也可作為 `subtitle-note-organizer` 的前置或附錄。

## 適用情境

- **課前 5 分鐘**：請 AI 對「今天要看的主題」吐一張條號地圖，上課邊聽邊在地圖上打勾
- **課中**：聽到老師連珠炮念條號跟不上時，對照地圖中的「回看影片對照提示」表
- **一試衝刺**：每個易混淆主題（無權處分 vs 無權代理、§107 vs §169 等）建一張，作為最後一個月的快速複習素材
- **錯題回饋**：寫考古題錯了，發現是條號張冠李戴 → 對該主題建一張條號地圖

## 指令格式

### 模式 A：依主題建立（最常用）

```
整理{科目}{主題}條號地圖
```

範例：
```
整理民法無權代理條號地圖
整理刑訴羈押條號地圖
整理行政法行政處分條號地圖
```

### 模式 B：從字幕段落產出

```
{字幕路徑}到{行數}整理條號地圖
```

範例：
```
課程字幕/民法/民法12.md到1012行整理條號地圖
```

### 模式 C：對照既有筆記更新

```
更新{條號地圖路徑}，加入{新增內容}
```

範例：
```
更新條號地圖/民法/無權代理與無權處分.md，加入§949 盜贓遺失物的細節
```

## 輸出位置

固定輸出到：

```
條號地圖/{科目}/{主題}.md
```

**科目資料夾**：民法、刑法、民事訴訟法、刑事訴訟法、行政法、憲法、公司法、保險法、票據法、強制執行法、證券交易法、國際公法、國際私法、法律倫理。

**檔名規則**：
- 單一主題：`{主題}.md`，例如 `羈押.md`
- 對照型主題：`{A 主題}與{B 主題}.md`，例如 `無權代理與無權處分.md`
- 不加日期、不加編號（同名直接覆蓋舊版，避免檔案爆炸）

## 輸出結構（固定 7 欄位）

每份條號地圖必須包含且只包含以下欄位，順序固定：

```markdown
# 條號地圖：{主題名稱}

> 主題：{科目}／{細分領域}
> 適用：2026 司律一試{科目歸類}
> 來源：{字幕檔/對話日期/手動建立}

---

## 0. 一句話總結
（1-3 句，把整個主題的核心判斷路徑壓到最短）

## 1. 最短一行筆記
（每條法條一行「功能標籤」，不抄全文，分組呈現。表格格式：條號 | 一行功能標籤）

## 2. 條號地圖
（用 ASCII 樹狀圖呈現條號之間的「起手→分支→救濟」路徑；
 若有對照關係，再附並列比較表）

## 3. 起手判斷流程
（3-5 步驟，告訴讀者面對該主題題目時應該依序問自己什麼問題）

## 4. 高頻混淆點
（一試最愛考的陷阱，每個陷阱一個小節，含「題幹特徵 → 應有反應」）

## 5. 回看影片對照提示
（核心欄位！表格：老師講出 X 條號 / 關鍵詞 → 你應該秒反應的功能句）

## 6. 實戰自我測驗
（3-5 題 30 秒內可作答的小題，含解答；驗證讀者是否能即時翻譯條號）

## 7. 30 秒複習版
（如果只剩 30 秒，用 3-4 句話濃縮整份地圖）
```

## 寫作原則

### 1. 條號功能標籤要短

> ❌ 「§169 規定由自己之行為表示以代理權授與他人或知他人表示為其代理人而不為反對之表示者，對於第三人應負授權人之責任，但第三人明知其無代理權或可得而知者，不在此限。」  
> ✅ 「§169：本人『自己製造授權外觀』或『知情不反對』→ 負授權人責任（表見代理）」

只記**功能 + 適用情境關鍵字**，不抄條文。讓讀者「看到條號就知道在處理什麼風險」即可。

### 2. 條號地圖要呈現「路徑」而非「清單」

ASCII 圖要明確標出：
- **起手條**（第一個套用的條）
- **分支條件**（什麼情況走左、什麼情況走右）
- **保護/救濟條**（最後落點）

範例：
```
              【170 I】無權代理 → 對本人不生效
                       │
        ┌──────────────┼──────────────┐
        ▼                              ▼
   有外觀（本人有歸責）          沒有外觀
        │                              │
        ├─【107】事後限制/撤回         ├─【170 II】相對人催告
        └─【169】授權外觀              ├─【171】善意相對人撤回
            ↓                          └─【110】向無權代理人求償
        本人要負責
```

### 3. 「回看影片對照提示」是本技能的命脈

這是與其他筆記類 skill 最大的差異欄位。每張地圖至少 8-15 列，把可能從老師口中冒出來的條號、口頭關鍵詞，全部映射到「秒反應的功能句」。

範例：
| 老師講出 | 你應該秒反應 |
| --- | --- |
| 「118」 | 無權處分起手 → 效力未定 |
| 「以自己名義」 | 物權路徑 → §118 線 |
| 「公示外觀」 | 善意取得線 |

### 4. 高頻混淆點要附「題幹特徵」

讓讀者在做考古題時能直接套用：

```markdown
### 陷阱 1：張冠李戴
> 題幹用「自己名義」賣，選項卻寫「§170 無權代理」→ 直接刪。
> 題幹用「本人名義」簽約，選項卻寫「§801 善意取得」→ 直接刪。
口訣：看名義先刪一半選項。
```

### 5. 不重複 `subtitle-note-organizer` 的內容

- **不抄法條全文**（那是 subtitle-note-organizer 的事）
- **不寫完整案例分析**（那是 subtitle-note-organizer 的事）
- **不附釋字/實務見解原文**（同上）

只做「條號之間的關係地圖 + 即時翻譯提示」。

## 執行步驟

### 步驟 1：確認主題範圍

從使用者指令解析：
- 科目（民法 / 刑法 / 行政法 …）
- 主題名稱
- 來源類型（憑既有知識整理 / 從字幕擷取 / 更新既有檔）

### 步驟 2：列出該主題的核心條號清單

依下列原則篩選：
- **起手條**（基本盤）：1-2 條
- **分支條**（外觀保護、要件分流）：3-5 條
- **救濟條**（相對人保護、例外限制）：2-4 條

**總條數控制在 6-12 條**。超過 12 條代表主題太大，應拆成兩張地圖。

### 步驟 3：依「輸出結構」依序產出 7 欄位

**特別注意**：
- 欄位 5「回看影片對照提示」必須涵蓋所有欄位 1 列出的條號
- 欄位 4「高頻混淆點」至少 3 個
- 欄位 6「實戰自我測驗」至少 3 題

### 步驟 4：寫入檔案

寫入 `條號地圖/{科目}/{主題}.md`。若資料夾不存在則建立。若同名檔已存在，先讀取舊內容比對，告知使用者差異後再覆蓋。

### 步驟 5：回報

回報訊息包含：
- 檔案路徑（連結）
- 收錄的條號清單（讓使用者快速確認有無遺漏）
- 建議的下一步動作（例如：搭配哪份字幕一起讀、可以做哪幾題考古題驗證）

## 品質檢查清單

寫完後自我檢查：

- [ ] 7 個欄位齊全且順序正確
- [ ] 每個條號都在「最短一行筆記」與「回看影片對照提示」中各出現一次
- [ ] 條號功能標籤每條不超過 2 行
- [ ] ASCII 地圖能正確呈現起手→分支→救濟路徑
- [ ] 高頻混淆點 ≥ 3 個，每個都有「題幹特徵 → 應有反應」
- [ ] 實戰自我測驗 ≥ 3 題，且都能 30 秒內作答
- [ ] 30 秒複習版濃縮在 4 句話內
- [ ] 沒有抄法條原文（只記功能標籤）
- [ ] 沒有侵入 subtitle-note-organizer 的內容範圍
